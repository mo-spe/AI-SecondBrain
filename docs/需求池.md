## 可以做了

### 多用户数据隔离与管理员管控
- 痛点：担心多用户数据隔离问题；需要管理员管控能力（权限、内容审核）；没法管理账号
- 方案：RBAC 角色权限体系 + 租户级数据隔离；管理员后台（用户管理、内容审核、资源配额控制）
- 备注：用户增长前的基础设施，越早做越好

### RAG 问答流式重构
- 痛点：RAG 问答完全同步阻塞，用户等 20-40s 无任何反馈（无流式输出）；向量检索是 Java 内存暴力扫描 O(n)，数据量大时变慢；不支持多轮对话追问
- 方案：引入 Spring AI 统一 LLM 调用抽象 + `StreamingChatClient` → SSE 逐字输出；PGVector HNSW 索引替换内存暴力搜索；改造为对话模式支持多轮上下文
- 备注：PRD 已出 → [rag-spring-ai-streaming-prd.md](prd/rag-spring-ai-streaming-prd.md)

### 知识标签层级化改造
- 痛点：Knowledge.vue「知识体系」侧边栏使用不存在的 `systemName` 字段做分组，永远走硬编码 fallback 假数据；后端 `/tags` API 完整但前端完全没对接；「知识体系」一词在三处使用但含义不同
- 方案：`knowledge_tag` 表加 `parent_id` 支持层级；侧边栏改为「知识标签」对接 `/tags` API 展示标签树；知识点卡片支持打标签/去标签；AI 在采集入库时自动建议标签
- 备注：PRD 已出 → [knowledge-tag-hierarchy-prd.md](prd/knowledge-tag-hierarchy-prd.md)

### 移动端 App 与微信小程序
- 痛点：学习行为发生在课间、通勤和睡前等碎片场景，Web 端无法稳定承接高频复习、AI 追问和社区浏览，影响 D1/D7 留存。
- 方案：复用现有 `mobile/` uni-app Vue 3 工程，一套源码产出 App、微信小程序和 H5；以今日复习为首屏留存闭环，同时提供知识浏览、AI 问答与社区浏览。
- 备注：已确认首发范围和技术路线（1D / 2A / 3A），PRD → [prd-mobile-app-wechat-mini-program.md](requirements/prd-mobile-app-wechat-mini-program.md)。MVP 跨端页面、社区详情路由、微信登录接口及构建基线已落地；上线前仍需配置 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`、合法 request 域名并完成真机验收。

### 知识社区与可信连接
- 痛点：大学生的现实社交圈有限，难以接触校内外在特定领域有经验的人；零散知识分享缺少真实问题承接，用户也难以依据持续、可信的知识贡献发现值得认识的人
- 方案：在现有知识广场上增加公开提问与多人回答，回答可引用或附带经用户明确授权公开的知识点；建设昵称展示、校园认证、个人主页、关注关系和按学校/专业/领域筛选的贡献榜，让用户沿着“问题 → 优质内容 → 贡献者主页 → 关注”建立连接
- 备注：MVP 不做联系请求和私信，先验证内容能否促成人物发现与关注；第一阶段已实现公开问题、回答、知识点公开快照、采纳与通知，第二阶段已实现公开个人主页、社区资料、关注/取消关注、粉丝/关注列表、拉黑/解除拉黑及作者深链。待依次执行 V10、V11 后联调；PRD → [knowledge-community-trusted-connections-prd.md](requirements/knowledge-community-trusted-connections-prd.md)
