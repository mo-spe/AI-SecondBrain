## 可以做了

### 多用户数据隔离与管理员管控
- 痛点：担心多用户数据隔离问题；需要管理员管控能力（权限、内容审核）；没法管理账号
- 方案：RBAC 角色权限体系 + 租户级数据隔离；管理员后台（用户管理、内容审核、资源配额控制）
- 备注：用户增长前的基础设施，越早做越好

### RAG 问答流式重构
- 痛点：RAG 问答完全同步阻塞，用户等 20-40s 无任何反馈（无流式输出）；向量检索是 Java 内存暴力扫描 O(n)，数据量大时变慢；不支持多轮对话追问
- 方案：引入 Spring AI 统一 LLM 调用抽象 + `StreamingChatClient` → SSE 逐字输出；PGVector HNSW 索引替换内存暴力搜索；改造为对话模式支持多轮上下文
- 备注：PRD 已出 → [rag-spring-ai-streaming-prd.md](prd/rag-spring-ai-streaming-prd.md)

### 知识标签层级化改造
- 痛点：Knowledge.vue「知识体系」侧边栏使用不存在的 `systemName` 字段做分组，永远走硬编码 fallback 假数据；后端 `/tags` API 完整但前端完全没对接；「知识体系」一词在三处使用但含义不同
- 方案：`knowledge_tag` 表加 `parent_id` 支持层级；侧边栏改为「知识标签」对接 `/tags` API 展示标签树；知识点卡片支持打标签/去标签；AI 在采集入库时自动建议标签
- 备注：PRD 已出 → [knowledge-tag-hierarchy-prd.md](prd/knowledge-tag-hierarchy-prd.md)
