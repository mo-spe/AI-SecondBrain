## 1. 执行摘要

### 问题陈述

当前 AI-SecondBrain 的知识节点仅在单用户上下文中存在——同一工作区内的成员可以看到共享的知识节点，但无法判断"谁正在编辑什么"，也没有细粒度的对外分享能力。用户需要：
1. 团队成员在同一工作区内协同编辑知识库
2. 将知识节点以只读方式分享给工作区外的人

### 解决方案

基于现有工作区 RBAC 体系（owner/admin/editor/viewer），新增**协作编辑锁**机制防止多人同时编辑同一节点导致内容丢失，以及**知识节点级对外分享**能力，支持生成只读分享链接。

### 成功标准

| KPI | 目标值 | 衡量方式 |
|-----|--------|----------|
| 编辑冲突率 | < 5% 的协作编辑会话发生冲突 | 编辑锁触发次数 / 总编辑会话数 |
| 分享功能使用率 | 上线 30 天内 >= 10% 活跃工作区使用过分享 | 分享链接生成次数 |
| 协作编辑延迟 | 编辑锁获取/释放 < 500ms | 后端 API 响应时间 P95 |
| 零数据丢失 | 无因协作冲突导致的内容覆盖丢失 | 用户报告 + 审计日志 |

## 2. 用户体验与功能

### 用户画像

| 角色 | 场景 | 核心诉求 |
|------|------|----------|
| 团队 Leader (Workspace Owner) | 带领 3-10 人团队共同维护领域知识库 | 控制谁可以编辑、查看编辑历史 |
| 知识贡献者 (Editor) | 在日常学习中编写和修改知识点 | 编辑时不被他人覆盖、知道谁在线 |
| 只读访问者 (Viewer / 外部用户) | 通过分享链接查看知识内容 | 无需注册帐号即可阅读 |

### 用户故事

**阶段一：工作区协作编辑**

| ID | 故事 | 验收标准 |
|----|------|----------|
| US-1 | 作为 Editor，我要编辑一个知识点时，系统应阻止其他人同时编辑同一节点，以免我的修改被覆盖 | 1. 用户进入编辑模式时自动获取编辑锁 2. 其他用户看到「xxx 正在编辑」提示 3. 用户离开编辑页或保存后自动释放锁 4. 锁超时时间 15 分钟，超时自动释放 |
| US-2 | 作为 Owner/Admin，我要邀请其他用户加入工作区，并指定角色 | 1. Owner/Admin 可输入用户 ID 发送邀请 2. Editor/Viewer 角色需被邀请人确认 3. 被邀请人收到通知后点击确认加入 4. 邀请 48 小时过期 |
| US-3 | 作为 Workspace 成员，我要看到知识节点的编辑历史 | 1. 每个知识节点有版本历史列表 2. 显示修改人、修改时间、变更摘要 3. 支持回滚到任意历史版本 |

**阶段二：知识节点对外分享**

| ID | 故事 | 验收标准 |
|----|------|----------|
| US-4 | 作为 Editor，我要将知识节点以只读链接分享给工作区外的人 | 1. 分享按钮生成唯一 URL 2. 链接可设置有效期（永久/7天/24小时） 3. 分享页只读渲染 Markdown，无需登录 4. 分享者可随时撤销链接 |
| US-5 | 作为 Owner，我要查看我分享出去的知识节点列表及访问统计 | 1. 管理后台列出所有分享记录 2. 显示创建时间、过期时间、访问次数 3. 支持批量撤销分享 |

### 非目标（本 PRD 不做）

- 多人同时实时协同编辑（类似 Google Docs）— 编辑锁方案已足够
- 知识节点外的其他实体分享（复习卡片、聊天记录等）
- 公开展厅/知识广场（属于 #3 社交功能 PRD 范围）
- 分支/合并工作流（类似 Git）

## 3. 技术规格

### 架构概览

```
前端                           后端                          数据层
───────                        ──────                        ──────
编辑页面 ──[获取锁]──▶  EditingLockController  ──▶  editing_lock 表
   │                        │
   ├──[保存内容]──▶  KnowledgeController  ──▶  knowledge_node 表
   │                        │                        │
   ├──[查看历史]──▶  KnowledgeController  ──▶  knowledge_revision 表
   │
分享设置 ──[生成链接]──▶  ShareController  ──▶  share_link 表
   │                        │
分享查看页 ──[访问链接]──▶  ShareController  ──▶  knowledge_node (只读)
```

### 新增数据表

#### editing_lock — 编辑锁

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| node_id | BIGINT UK | 知识节点 ID |
| user_id | BIGINT | 持有锁的用户 ID |
| acquired_at | DATETIME | 锁获取时间 |
| expires_at | DATETIME | 锁过期时间（默认 +15min） |

- 唯一约束：同一知识节点只有一条锁记录
- 清理策略：定时任务每分钟清理过期锁

#### knowledge_revision — 版本历史

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| node_id | BIGINT INDEX | 知识节点 ID |
| user_id | BIGINT | 编辑用户 ID |
| title | VARCHAR(500) | 快照标题 |
| content_md | LONGTEXT | 快照内容 |
| summary | TEXT | 快照摘要 |
| revision_num | INT | 版本号（自增） |
| change_summary | VARCHAR(500) | 变更说明 |
| created_at | DATETIME | 创建时间 |

#### share_link — 分享链接

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| node_id | BIGINT INDEX | 知识节点 ID |
| owner_id | BIGINT | 分享者用户 ID |
| token | VARCHAR(64) UK | 随机分享令牌 |
| expire_type | VARCHAR(20) | permanent / 7d / 24h |
| expires_at | DATETIME | 具体过期时间（nullable） |
| access_count | INT | 累计访问次数 |
| is_revoked | TINYINT | 是否已撤销 |
| created_at | DATETIME | 创建时间 |

### API 设计

#### 编辑锁

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/knowledge/{nodeId}/lock` | 获取编辑锁 |
| DELETE | `/knowledge/{nodeId}/lock` | 释放编辑锁 |
| GET | `/knowledge/{nodeId}/lock` | 查询锁状态（持有者、剩余时间） |

#### 版本历史

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/knowledge/{nodeId}/revisions` | 版本历史列表 |
| GET | `/knowledge/{nodeId}/revisions/{revId}` | 版本详情（diff 用） |
| POST | `/knowledge/{nodeId}/revisions/{revId}/rollback` | 回滚到指定版本 |

#### 分享

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/share` | 创建分享链接 `{ nodeId, expireType }` |
| GET | `/share/{token}` | 公开访问分享内容（无需鉴权） |
| DELETE | `/share/{id}` | 撤销分享 |
| GET | `/share/list` | 我的分享列表（含访问统计） |

#### 邀请增强（现有接口改造）

| 方法 | 路径 | 说明 |
|------|------|------|
| PUT | `/workspace/{id}/members/{userId}/accept` | 被邀请人确认加入 |

### 编辑锁生命周期

```
用户点击「编辑」
  → POST /knowledge/{id}/lock
    → 锁存在且未过期 → 409 Conflict，返回当前持有者信息
    → 锁不存在或已过期 → 获取成功，返回锁信息
用户编辑中（每 5 分钟前端自动续期）
  → POST /knowledge/{id}/lock (renew)
用户保存或离开页面
  → DELETE /knowledge/{id}/lock
    → 同步创建 knowledge_revision 记录
超时（15 分钟无续期）
  → 定时任务清理，下次任何人可获取锁
```

### 安全性

| 层 | 措施 |
|------|------|
| 编辑锁 | 仅工作区 editor/admin/owner 可获取；viewer 拒绝 |
| 版本历史 | 仅工作区成员可查看 |
| 分享链接 | token 使用 SHA-256 随机生成，64 字符，不可猜测 |
| 分享页 | 无鉴权访问，仅渲染 Markdown 内容，不暴露原始 API |
| 回滚 | 仅 owner/admin 可执行回滚操作 |

## 4. 风险与路线图

### 分阶段交付

```
MVP (V1.0) — 工作区协作基础
├── 编辑锁 (获取/释放/超时)
├── 版本历史 (自动保存快照 + 查看历史列表)
├── 回滚到历史版本 (owner/admin)
└── 邀请确认流程 (被邀请人需确认)

V1.1 — 知识节点对外分享
├── 生成分享链接 (永久/7天/24小时)
├── 公开查看页 (无鉴权 Markdown 渲染)
├── 分享管理 (列表/撤销)
└── 访问统计

V1.2 — 协作增强
├── 编辑锁自动续期 (前端心跳)
├── 工作区内「谁在线」状态
├── 版本 diff 对比视图
└── 批量操作 (批量分享/撤销)
```

### 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 编辑锁死锁（用户关闭浏览器未释放） | 中 | 低 | 15 分钟超时自动释放 + 管理员手动强制解锁 |
| 编辑锁高并发下竞态条件 | 低 | 高 | 数据库唯一约束 + INSERT ON DUPLICATE 原子操作 |
| 分享链接被爬虫/滥用 | 中 | 中 | token 足够长不可穷举；可加验证码；访问频率限制 |
| knowledge_revision 表增长过快 | 中 | 低 | 每次保存才记录；定期归档超过 90 天的历史 |

### 与现有系统的兼容性

| 现有系统 | 影响 |
|------|------|
| 工作区 RBAC | 无需改动，复用 owner/admin/editor/viewer 角色 |
| KnowledgeNode 实体 | 无需改表，userId/workspaceId 字段已存在 |
| 前端 Knowledge 编辑页 | 需增加编辑锁获取/释放逻辑 |
| 前端路由 | 新增分享查看路由 `/share/:token`（无需 MainLayout） |

## 5. 验收测试场景

1. **编辑锁正常流程**：用户 A 编辑节点 X → 用户 B 尝试编辑同一节点 → B 看到「A 正在编辑」提示，无法进入编辑模式
2. **编辑锁超时**：用户 A 编辑节点 X 但关闭浏览器 → 15 分钟后用户 B 可正常编辑
3. **版本回滚**：用户 A 修改节点 X 3 次 → Owner 查看历史列表 → 回滚到第 1 版 → 节点内容恢复
4. **分享链接**：用户 A 生成节点 X 的分享链接（7 天有效）→ 未登录用户打开链接 → 看到只读 Markdown 内容
5. **撤销分享**：用户 A 撤销分享链接 → 原链接打开显示「链接已失效」
6. **邀请确认**：Owner 邀请用户 B（Editor 角色）→ 用户 B 收到通知确认 → 用户 B 加入工作区
