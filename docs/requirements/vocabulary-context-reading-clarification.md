# 截图词表生成语境文章 PRD

> 状态：需求已确认，开发中  
> 版本：v1.0  
> 日期：2026-10-05  
> 目标端：Android；个人空间

## 1. Executive Summary

### 问题与方案

用户每天在背词应用学习约 50 个词，想上传当天单张或多张词表截图，再读一篇自然的英文文章，在语境中复现这些词。现有 Android 端没有词表校对、文章生成或覆盖核验。**截图只有图片时，视觉 AI 提取是硬性步骤；不使用 OCR 冒充成功。**后端使用用户配置的视觉模型 API Key 提取候选词，用户确认词表后生成文章，程序逐词校验覆盖，阅读时点词查看语境释义。

### 成功标准

- 一次任务支持 1–8 张截图，每张不超过 4 MB、合计不超过 24 MB；跨图重复词合并，无法辨认的词提示待确认。
- 用户可编辑候选词，只有确认后的词表参与写作。识别失败时保留图片与手工修改。
- 文章为一篇完整、自然分段的英文正文；目标词先按语义或场景规划到段落，篇幅随词数增加。显示程序核验的 `X/N` 和缺失词，绝不依据模型自报数字显示 `50/50`。
- 目标词可点击查看该句的中文语境释义；记录可在个人空间再次阅读。

## 2. User Experience & Functionality

### 用户故事与验收条件

1. **导入**：用户从相册选择单张或多张图片，能预览、移除与重新选择。识别前告知图片会发往用户选定的模型服务商；未配置个人视觉模型及 Key 时不上传，展示配置入口。
2. **提取与校对**：视觉 AI 返回候选英文词、来源图片序号和不确定标记。用户可删除误识别项、补录漏词、改正拼写；大小写不敏感去重。空词表不能生成文章。
3. **写作**：用户确认词表，默认中级难度与日常/学习主题，生成约 900–1300 个英文词的一篇文章。失败后保留确认词表，允许重试。
4. **覆盖与阅读**：后端以独立单词边界逐一校验，首版只认完全相同词形（忽略大小写），不把 `art` 计入 `cart`，不默认把复数或过去式计入覆盖。生成前按语义或场景安排段落；缺词时最多局部修订两次，仍缺失则在正文末尾生成一次明确标注的补充阅读，再由程序复核并列出最终缺词。点词显示当前语境释义，未生成释义时明确提示。
5. **重读**：词表、文章、覆盖结果及语境释义保存在用户个人记录中，可再次打开；不自动进入普通知识库或复习排期。

核心流程：`选择图片 → 明示发送范围 → 视觉 AI 提取 → 用户校对 → 文章生成 → 程序复核覆盖 → 点词阅读 → 保存/重读`。

首版不自动读取第三方背词应用数据，不自动分享文章，不保证未经核对的识别结果 100% 正确，不自动识别词形变体。

## 3. AI System Requirements

### 工具、输入与输出

复用现有 `UserAiConfig`、`UserAiProviderKey` 和 `AiService`，扩展图片输入，不重复建立 AI Client 或 RAG。错题默认仍是设备端 OCR；只有配置个人 Key 并主动启用才调用视觉 AI。词表截图始终由视觉 AI 提取，未配置 Key 时不降级为 OCR。用户的 Key 仅在后端解密调用，不能放到 Android 包或日志里，也不能偷偷回退到系统 Key。

视觉模型只提取截图中可见的目标英文词，结构化返回 `word`、`sourceImageIndex`、`uncertain`；不应抽取按钮、例句、中文释义或猜测看不清的词。后端校验 JSON、词数与词形并去重。文章模型只接收用户确认后的文本词表、难度、主题，先按语义/场景规划目标词到段落，再返回分段正文与语境释义。程序检查目标词独立词边界和释义完整性；最多两次只修订局部段落，减少整篇重写；若仍有缺词，再生成一次补充阅读。覆盖率完全由程序复核；模型内容只是候选。

### 守则与评估

限制图像格式、张数、大小、分辨率和请求超时；不记录原图、密钥或含隐私的模型完整输出。模型不得把未见到的词冒充已识别。用单图、多图真实截图各至少 30 组评估词表精确率、召回率、人工修正时间和单位任务费用；用 30 组真实词表人工评审文章连贯性、语法、难度和自然度。正式模型选型依实测，不预设准确率。

## 4. Technical Specifications

Android Compose 增加词表文章入口与选图、词表校对、阅读页面；临时输入在网络失败后仍保留。后端提供已登录的多图 `multipart/form-data` 识别接口、文本词表生成接口、个人历史接口。图像经后端转发给现有模型提供商，生成阶段不发送图像。记录至少包含 `user_id`、确认词表、正文、语境释义、覆盖数、缺失词、创建时间；如需持久化，新增表而不改已有表。所有读取按 JWT 用户隔离。

服务端校验 MIME、大小、张数和真实图片内容；空图、可执行文件、非法模型 JSON 分别返回可读错误。测试至少覆盖无 Key、异常 JSON、跨图去重、大小写去重、独立词边界、缺词与越权读取。构建后用真实设备完成单图、多图各一次导入、校对、生成、重开阅读。

## 5. Risks & Roadmap

第一阶段接入个人 Key 下的图片输入、错题可选精准识别、词表多图提取与校对；第二阶段完成文章生成、覆盖核验、阅读和历史；第三阶段用真实截图与数学题照片优化模型与费用。小字漏词、公式幻觉、分散词生硬入文和费用失控的缓解方法分别是人工校对、保留原图、程序复核、限制重试并记录实际 token 成本。

参考：[千问视觉模型文档](https://help.aliyun.com/zh/model-studio/qwen3-vl-flash)、[Gemini 图像理解文档](https://ai.google.dev/gemini-api/docs/image-understanding)。项目现状见 `android/app/src/main/java/com/secondbrain/android/ui/StudyArchiveViewModel.kt` 与 `backend/src/main/java/com/secondbrain/service/impl/AiServiceImpl.java`。

## 词汇覆盖率改进（2026-10-05）

- 文章初稿要求模型先按语义或场景分组并规划段落；目标词超过 25 个时将建议篇幅提高到 1400–1800 词，避免在短文中硬塞大量目标词。
- 覆盖核验后最多尝试两次局部段落替换；如果替换没有提高程序计算的覆盖数则停止修订，避免重复消耗模型调用。仍未覆盖的词会触发一次独立的补充阅读生成，追加在同一篇记录中并继续逐词核验。
- 最终覆盖数仍由后端独立计算；补充阅读未能覆盖的词会继续显示为缺失，不会被模型自报覆盖率覆盖。

## 文章入库后连接中断修复（2026-10-08）

- 用户提供的日志显示：21:16:34 文章插入返回 `Updates: 1`，随后 Tomcat 写入响应时抛出 `ClientAbortException / Connection reset by peer`。异常处理器再次写入错误 JSON，产生第二段异常。现有日志支持“保存后响应连接已断开”，不能单凭日志区分客户端超时、网络中断或用户关闭页面。
- 发现 Android 全局读取时限为 120 秒，而文章初稿、最多两次局部修订及一次补充阅读会连续调用模型，每次服务端读取时限为 120 秒。生成总耗时可能超过手机等待时限。
- Android 通过专用 `Call.Factory`，仅对 `POST /vocabulary/articles` 和 `POST /vocabulary/articles/{id}/complete` 使用 10 分钟读取时限、630 秒总调用时限；在调用创建前配置总时限，使计时器实际生效。历史查询、截图提取和其他请求保留原时限。模型写作请求关闭连接失败自动重试，避免响应丢失后自动重复生成。
- 生成或补齐发生网络异常时保留词表草稿或原文章，提示结果可能已经保存，并自动查询历史。词表页始终显示“刷新历史文章”，支持后端稍后完成后的手动恢复。读取历史不会自动生成或自动选择文章。生成请求在启动协程前进入忙碌状态，阻止连续点击重复提交。
- 后端针对 `ClientAbortException` 使用无响应体的独立处理器，仅记录调试信息；其他 I/O 和业务异常继续使用原有错误响应。
