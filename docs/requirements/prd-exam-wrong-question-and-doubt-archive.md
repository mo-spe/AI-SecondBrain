# 考研错题与疑问归档 PRD

> 文档状态：已确认，实施中
> 版本：v1.2
> 更新时间：2026-10-05
> 目标端：Android
> 适用范围：个人考研学习场景

## 1. Executive Summary

### Problem Statement

考研用户在习题册、课本和讲义上会持续产生错题与暂时无法解决的疑问。当前 Android 端可以保存知识和进行普通复习，但缺少以照片为入口的错题档案、书籍页码来源、错误类型、疑问理解迭代和用户自主排期能力，导致纸面记录无法稳定沉淀为可回看的个人学习资料。

### Proposed Solution

新增个人“错题本”和“疑问箱”。用户拍照后即可保存原始资料，再补充书名、页码和备注；默认使用设备端 OCR。用户自行配置 API Key 后，可主动选择视觉 AI 精准识别，再对照原图确认结果。错题和疑问默认不进入复习队列，只有用户主动设置复习或处理时间后才进入今日任务；疑问支持持续追加个人理解，直到用户确认解决。

### Success Criteria

- 用户从拍照到保存一条错题或疑问档案的核心流程不超过 3 个必填步骤。
- 100 条测试图片中，原图上传成功率达到 99%；OCR 与可选视觉 AI 结果均可编辑，不因识别失败阻断归档。
- AI 建议的错误类型和知识点中，用户接受或修改后可用率达到 80% 以上。
- 未设置时间的错题和疑问在 `GET /review/today` 中出现数量为 0；用户主动设置时间后，只有到期记录进入今日任务。
- 用户可以在错题详情中看到原图、来源、复盘记录和当前状态；在疑问详情中看到完整的理解迭代历史。

## 2. User Experience & Functionality

### User Personas

- **考研备考者**：使用习题册和讲义学习，需要快速保存错题，后续按自己的节奏复盘。
- **阶段性整理者**：当天无法解决疑问，希望先记录来源和上下文，之后集中处理。

第一版只支持个人使用。记录默认私有，不进入工作区公共题目池，不影响其他成员的知识库和复习计划。

### User Stories and Acceptance Criteria

#### Story 1：拍照归档错题

**User Story**：作为考研用户，我想拍下做错的题目并立即保存，以便之后整理和复盘。

**Acceptance Criteria**：

- 用户可以从 Android 端拍照或选择已有图片创建错题。
- 图片在本地草稿保存成功后，即使网络暂时不可用也不能丢失。
- 用户至少可以填写或确认科目、书名和页码；页码允许为空，但页面需要提示补充。
- 原图、缩略图和创建时间被保存，详情页可以重新查看原图。
- OCR 识别失败或用户未配置 AI Key 时仍可只保存图片和手工信息。
- 新建错题默认状态为“未安排”，`nextReviewTime` 为空。

#### Story 2：AI 辅助整理错题

**User Story**：作为考研用户，我想让 AI 从照片中提取题目和知识点，减少手工整理时间。

**Acceptance Criteria**：

- AI 可以返回题干与公式转写、科目、章节、知识点建议；一张图片有多道题时需标记题号和题目边界，让用户选择或裁剪要归档的题。
- 数学表达式优先保留可编辑的 LaTeX 或纯文本转写，并与原图并排校对；无法看清时返回“待确认”，不能补造符号、数字或条件。
- 仅凭题目照片通常无法判断用户为什么做错；错误类型默认由用户填写。有手写解题过程或用户备注时，AI 才能提出候选错误类型，仍需用户确认。
- AI 结果必须显示为“建议”，用户可以逐项修改、删除或补充。
- AI 失败、超时或识别内容无法确认时，页面仍允许手工保存。
- AI 不得自动把错题标记为已掌握，也不得自动设置复习时间。
- AI 建议和用户最终确认值分别保存，便于后续评估质量。
- 照片无法确定书名或页码时，AI 不得伪造确定值；应显示为空或“待确认”。

#### Story 3：管理错题来源和错误类型

**User Story**：作为考研用户，我想知道错题来自哪本书哪一页，以及自己为什么做错，以便按薄弱点复盘。

**Acceptance Criteria**：

- 错题详情显示书名、页码、科目、章节和知识点。
- 错误类型至少支持：概念不清、公式记错、计算错误、审题错误、方法不会、粗心、不确定。
- 用户可以修改来源和错误类型，不需要重新上传图片。
- 用户可以添加个人备注，例如“二阶导数符号判断错误”。
- 列表可以按书名、章节、知识点、错误类型和状态筛选。

#### Story 4：用户主动安排错题复习

**User Story**：作为考研用户，我想自己决定什么时候复习错题，而不是被系统自动安排。

**Acceptance Criteria**：

- 新错题不自动进入今日复习。
- 用户可以主动选择“明天、3 天后、下周或自定义日期时间”。
- 用户未设置时间时，错题保持“未安排”，仍可以从错题本手动打开。
- 用户可以在详情页修改、取消或推迟复习时间。
- 推迟只修改 `nextReviewTime`，不删除错题和历史复盘记录。
- 到期前不进入今日任务，到期后进入今日任务。
- 复盘完成后，系统不自动安排下一次时间；页面提供“安排下一次复习”操作，由用户决定是否设置。
- 用户可以将错题标记为“已掌握”；已掌握记录不进入今日任务，但历史信息保留。

#### Story 5：以原始照片为主完成错题复盘

**User Story**：作为考研用户，我想先看原始题目并重新回忆，再查看解析，避免直接看答案。

**Acceptance Criteria**：

- 复盘页优先展示错题原图。
- 用户可以展开或隐藏个人答案、正确答案、解析和错误原因。
- 用户可以记录本次复盘结果：答对、答错或仅查看。
- 复盘记录包含时间、结果和用户新增备注。
- 复盘结束后可以返回错题详情，并选择是否安排下一次时间。

#### Story 6：拍照归档暂时无法解决的疑问

**User Story**：作为考研用户，我想把课本或讲义中的疑问先记录下来，避免因为暂时无法解决而遗忘。

**Acceptance Criteria**：

- 用户可以拍照或输入文字创建疑问。
- 用户可以填写书名、页码、章节和疑问提出处。
- 疑问类型至少支持：概念理解、公式推导、解题步骤、例题看不懂、知识点关系、资料说法不一致。
- 新疑问默认状态为“待处理”，不会自动进入今日复习。
- 用户可以设置下次处理时间；未设置时只保存在疑问箱中。
- 疑问详情显示原始图片、疑问内容和来源信息。

#### Story 7：记录个人理解的迭代过程

**User Story**：作为考研用户，我想保留自己对疑问的多次理解变化，以便回看思考过程。

**Acceptance Criteria**：

- 用户可以不断追加“我的理解”，不能只覆盖旧内容。
- 每次理解记录包含正文和创建时间。
- 用户可以将当前理解标记为“初步理解”“待验证”或“已确认”。
- 用户确认疑问已解决后，状态变为“已解决”，但所有历史理解仍可查看。
- 用户可以重新打开已解决疑问，状态回到“待处理”，历史记录不删除。
- AI 提供的解释必须与用户理解分开显示，并允许用户标记“有帮助/无帮助”。

### Core User Flows

#### 错题归档流

```text
拍照或选择图片
    ↓
本地保存草稿
    ↓
设备端 OCR（默认）或用户主动选择视觉 AI 精准识别（需个人 Key）
    ↓
用户确认书名、页码、知识点、错误类型
    ↓
保存为“未安排”错题
    ↓
用户主动设置复习时间
```

#### 错题复盘流

```text
从错题本手动打开，或从今日任务进入
    ↓
先看原始照片并回忆
    ↓
查看解析并记录本次结果
    ↓
可选：安排下一次复习 / 推迟 / 标记已掌握
```

#### 疑问整理流

```text
拍照或输入疑问
    ↓
保存来源和提出处
    ↓
保持“待处理”或设置下次处理时间
    ↓
追加个人理解
    ↓
验证后标记“已解决”
```

### Non-Goals

第一版不包含：

- 工作区共享错题和公共疑问；
- 多人协作回答和评论；
- 完整教材、版本和目录管理；
- AI 自动判定用户已经掌握或疑问已经解决；
- AI 自动设置或修改错题复习时间；
- 自动生成大量相似题；
- 按考研日期自动推算完整学习计划；
- 替换现有普通知识卡片的复习算法。

## 3. AI System Requirements

### Tool Requirements

- Android 图片采集能力：调用现有拍照/相册和本地草稿能力。
- 设备端 OCR：默认提取原图文字，失败不阻断归档。
- 视觉 AI 能力：只有用户配置自己的 API Key 并主动启用时才接收图片，提取题干、公式与知识点建议；公式识别失败时保留原图。
- 现有 AI Model Client：目前只支持字符串消息；需在现有模型配置与调用路径中扩展图片输入和结构化输出，用于提取科目、章节、知识点和错误类型建议。
- 现有知识检索能力：在用户确认后，可辅助匹配已有知识点；匹配结果必须允许用户修改。
- 现有认证与文件存储：图片和 AI 请求必须绑定当前用户。

### AI Input and Output

AI 输入包括：

- 原始图片及可选的用户手工修正文本；
- 用户填写的科目、书名、页码；
- 可选的用户备注；
- 当前用户已有知识点列表，用于匹配建议。

AI 输出建议使用结构化 JSON：

```json
{
  "ocrText": "题干文字和公式 LaTeX（沿用现有字段名；精准识别时由视觉 AI 转写）",
  "subject": "考研数学",
  "chapter": "极限与连续",
  "knowledgePoints": ["夹逼定理"],
  "errorType": "概念不清",
  "sourceBook": "高等数学",
  "sourcePage": "126",
  "confidence": 0.82,
  "needsConfirmation": ["sourceBook", "sourcePage"]
}
```

### AI Guardrails

- AI 结果只能作为建议，最终值以用户确认结果为准。
- 无法从原图确认的字段显示“待确认”，不能把模型自报的置信度当作可靠的准确率。
- AI 不得替用户判断“已掌握”“已解决”。
- AI 不得在用户未操作时创建复习排期。
- AI 不得修改用户已有的错题、疑问和理解历史。
- 公式、页码和书名无法可靠识别时，优先返回空值并保留原图。
- 原图只显示题目而没有用户的错误过程时，不得把某种错误类型写成已确定事实。

### Evaluation Strategy

第一版上线前建立至少 100 张考研数学错题图片的离线评估集，覆盖清晰照片、倾斜照片、手写答案和公式图片。

- 题干与公式转写经人工判定的可读率目标：≥90%；分别记录题号、上下标、分式、极限和手写内容的错误率。
- 错误类型 Top-1 建议准确率目标：≥80%。
- 已有知识点匹配 Top-3 覆盖率目标：≥85%。
- 书名和页码无法从图中确定时不得被强制填充。
- 线上统计用户接受、修改和清空 AI 建议的比例，按版本监控质量。

### 视觉模型试点与成本控制（2026-10-05 修订）

- Android 保留本地 ML Kit OCR 默认路径。视觉图片输入与独立按钮已在本轮开发，但尚未用真实考研数学照片验证识别质量；下面的模型质量门槛仍是上线前待完成的评估。
- 首先用已有千问服务商配置接入支持图片输入的低成本视觉模型，候选为 `qwen3-vl-flash`；复杂公式和手写图片在离线评估中达不到质量门槛时，再选择性升级到 `qwen3-vl-plus`。模型费用按实际图片 token、输出 token、重试和地域统计，不仅比较模型标价。
- Android 端保留原图与本地草稿。只有用户主动点击“视觉 AI 精准识别”时，图片才经后端转发给模型服务商；未配置个人 Key 时拒绝调用，不回退到系统 Key。不要在 Android 客户端放置服务商密钥，也不要把图片数据记入请求日志。
- 单图多题优先提供选题/裁剪入口；清晰度不足时提示重拍，不能为了减少 token 而把公式压缩到不可读。
- 识别结果、原图和用户最终修改值并排可追溯。优先用便宜模型完成常规图片，只对失败或低质量样本重试或升级；限制自动重试次数。
- 候选模型与价格来源：阿里云百炼 `qwen3-vl-flash` 和 `qwen3-vl-plus` 官方文档。开发实施前重新核对实时价格与可用地域。

## 4. Technical Specifications

### Architecture Overview

```text
Android Compose
  ├─ 相机/相册 → 本地草稿
  ├─ 错题本 → 错题档案 API
  ├─ 疑问箱 → 疑问档案 API
  └─ 今日复习 → 现有复习 API
          ↓
Spring Boot API
  ├─ 文件存储
  ├─ 视觉 AI 建议服务（复用现有模型配置）
  ├─ 错题与疑问个人数据
  └─ 现有 user_review_card 排期能力
```

错题档案和疑问档案属于用户个人数据。它们可以携带 `workspaceId` 作为来源上下文，但第一版的可见范围固定为创建者本人。

### Proposed Data Model

#### `wrong_question_record`

| 字段 | 说明 |
|---|---|
| `id` | 错题档案 ID |
| `user_id` | 所属用户 |
| `workspace_id` | 来源工作区，可为空；不代表共享可见 |
| `image_url` | 原始错题图片 |
| `ocr_text` | 默认 OCR 文本，用户启用精准识别后可由其确认的视觉 AI 转写覆盖；可为空 |
| `subject` | 科目 |
| `source_book` | 书名或资料名 |
| `source_page` | 页码，可为空 |
| `chapter` | 章节，可为空 |
| `knowledge_points` | 用户确认的知识点 |
| `error_type` | 用户确认的错误类型 |
| `user_note` | 个人备注 |
| `review_status` | `UNSCHEDULED/SCHEDULED/MASTERED/ARCHIVED` |
| `next_review_time` | 用户主动设置的时间，可为空 |
| `last_review_time` | 最近一次复盘时间 |
| `created_at` / `updated_at` | 创建和更新时间 |

#### `wrong_question_ai_suggestion`

保存 AI 原始建议、模型版本和用户最终确认值，避免后续无法评估 AI 质量。模型自报置信度只能用于提示，实际质量以用户修改率和离线标注集评估。建议与错题档案一对一或一对多保存，保留最近一次建议即可作为 MVP。

#### `wrong_question_review_log`

保存每次手动复盘的结果：错题 ID、用户 ID、复盘时间、结果、备注和当时图片/解析版本。该记录不负责生成下一次排期。

#### `doubt_record`

| 字段 | 说明 |
|---|---|
| `id` | 疑问 ID |
| `user_id` | 所属用户 |
| `workspace_id` | 来源工作区，可为空 |
| `image_url` | 讲义或课本图片，可为空 |
| `content` | 疑问正文 |
| `source_book` | 书名或资料名 |
| `source_page` | 页码 |
| `chapter` | 章节 |
| `doubt_type` | 疑问类型 |
| `status` | `PENDING/UNDERSTOOD/VERIFYING/RESOLVED` |
| `next_process_time` | 用户主动设置的处理时间，可为空 |
| `created_at` / `updated_at` | 创建和更新时间 |

#### `doubt_understanding_revision`

保存疑问的理解迭代：疑问 ID、正文、理解状态、创建人和创建时间。只追加不覆盖，确保用户可以回看自己的理解变化。

### Review Integration

错题档案本身不直接等同于普通知识卡片。用户点击“安排复习”时，系统可以创建或绑定一条现有个人复习任务，复习任务增加来源类型和来源 ID，例如 `sourceType=WRONG_QUESTION`、`sourceId=123`；复习页面根据来源加载错题原图。

规则如下：

- 未安排的错题不创建待复习任务。
- 用户取消排期时，清除或停用对应任务，但保留错题档案和复盘历史。
- 用户提交复盘结果后，不自动计算下一次时间。
- 用户主动设置下一次时间时，更新任务的 `nextReviewTime`。
- 普通知识卡片仍沿用现有排期逻辑，两个入口不能互相覆盖排期。

### Proposed API Surface

以下接口列出现有实现与后续计划；精准识别使用新建档案前的临时原图，不依赖已存档 ID：

| 方法 | 接口 | 用途 |
|---|---|---|
| `POST` | `/study/wrong-questions` | 创建错题档案或保存草稿 |
| `POST` | `/study/wrong-questions/recognize` | 用户主动上传单张原图，请求个人视觉模型转写与整理建议 |
| `PATCH` | `/study/wrong-questions/{id}` | 修改来源、知识点、错误类型和备注 |
| `GET` | `/study/wrong-questions` | 分页、筛选错题 |
| `GET` | `/study/wrong-questions/{id}` | 查看错题详情和复盘记录 |
| `POST` | `/study/wrong-questions/{id}/schedule` | 用户主动设置或取消复习时间 |
| `POST` | `/study/wrong-questions/{id}/reviews` | 写入一次手动复盘记录 |
| `POST` | `/study/wrong-questions/{id}/master` | 标记已掌握 |
| `POST` | `/study/doubts` | 创建疑问 |
| `PATCH` | `/study/doubts/{id}` | 修改疑问来源和状态 |
| `GET` | `/study/doubts` | 分页、筛选疑问 |
| `POST` | `/study/doubts/{id}/understandings` | 追加一次理解迭代 |
| `POST` | `/study/doubts/{id}/analyze` | 请求 AI 解释或关联知识点 |
| `POST` | `/study/doubts/{id}/schedule` | 设置或取消下次处理时间 |

所有接口必须从 JWT 获取 `userId`，不能接受客户端传入的 owner 用户 ID 作为权限依据。

### Security & Privacy

- 错题照片、疑问照片和个人理解默认仅当前用户可见。
- 工作区成员不能通过题目池接口读取个人错题或疑问。
- 图片访问使用带权限校验的资源接口，不能仅凭 URL 直接越权读取。
- AI 请求只发送完成任务所需的图片和文本，记录模型版本和请求状态。
- 删除错题时采用软删除或归档，避免误操作导致复盘历史无法追溯。
- 用户切换工作区后，必须重新按当前用户和来源上下文查询，不能把不同空间的个人记录混在一起。

## 5. Risks & Roadmap

### Phased Rollout

#### MVP

- Android 拍照/相册创建错题和疑问；
- 本地草稿和服务端归档；
- 书名、页码、科目、章节、错误类型和疑问类型；
- 设备端 OCR 默认转写；用户配置个人 Key 后可主动使用视觉 AI 精准识别，结果仍需确认；
- 错题和疑问默认不排期；
- 用户手动设置、修改、取消和推迟时间；
- 错题原图复盘；
- 疑问理解迭代和状态管理；
- 个人列表、详情、筛选和搜索。

#### v1.1

- 根据已确认知识点联动知识详情；
- AI 生成错题解析和疑问验证题；
- 薄弱知识点和错误类型统计；
- 图片草稿批量整理；
- 复盘记录导出。

#### v2.0

- 真题年份、试卷和题型结构化管理；
- 考研目标日期和用户可选的阶段计划；
- 工作区内主动分享疑问和错题讨论；
- 基于用户确认数据的个性化推荐。

### Technical Risks

- **视觉识别质量不稳定**：公式、手写答案和倾斜照片仍可能被漏读或补造，因此必须保留原图并允许手工修改。
- **AI 误分类**：错误类型和知识点只能作为建议，不能让 AI 结果直接改变用户的复习状态。
- **图片存储成本**：原图和缩略图需要限制大小、压缩和清理策略，但不能压缩到无法阅读。
- **复习模型兼容**：错题采用用户手动排期，必须与现有自动排期卡片区分来源，避免提交错题后被旧逻辑自动安排。
- **历史理解不可追溯**：疑问必须使用追加式理解记录，不能用单字段覆盖旧理解。
- **离线与重复提交**：拍照归档和 AI 分析需要支持草稿、重试和幂等，避免网络重试生成重复档案。

### 已确认的 MVP 决策

- 拍照内容先保存在设备草稿，网络恢复后由用户保存到个人档案；服务器保存成功前草稿不删除。
- 书名和页码允许为空，用户可以之后补充。
- 错题复盘结果由用户手动记录；结果不会自动产生下一次排期。
- 错题排期完全由用户控制：未设置时间不进入今日处理，完成复盘后清除本次排期，用户可再主动安排。
- 已掌握错题保留档案和复盘历史，不进入今日处理；第一版暂不提供从“已掌握”直接恢复排期的操作。
- 疑问允许用户直接标记解决，也允许之后重新打开；不强制答验证题。
- AI 建议快照与用户确认字段分开保存，第一版保留最近一次建议快照。
