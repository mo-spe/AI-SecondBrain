## 1. Executive Summary

### Problem Statement

用户的学习行为发生在碎片化移动场景，当前 Web 端无法稳定承接“随手打开、快速复习、持续追问、浏览社区”的高频入口，导致知识系统难以形成日常使用习惯。

### Proposed Solution

以现有 `mobile/` uni-app 为统一跨端基础，首发提供登录、今日复习、知识浏览、AI 问答和社区浏览五个高频能力。通过每日复习首页、连续学习反馈、快捷入口、跨端登录态和轻量通知形成“打开应用 → 完成一组复习 → 获得反馈 → 继续追问/浏览”的留存闭环。

### Success Criteria

| 指标 | 首发 4 周目标 | 口径 |
|------|---------------|------|
| 移动端激活率 | >= 65% | 首次登录后 24 小时内完成一次复习或浏览知识 |
| D1 留存 | >= 35% | 注册用户次日通过 App/小程序访问 |
| D7 留存 | >= 18% | 注册用户第 7 天仍有一次有效学习行为 |
| 复习任务完成率 | >= 45% | 当日打开移动端且完成至少一张卡片的用户 |
| 跨端登录成功率 | >= 98% | 合法登录请求成功且正确进入复习首页 |

## 2. User Experience & Functionality

### User Personas

| 用户 | 场景 | 目标 |
|------|------|------|
| 碎片学习者 | 通勤、课间、睡前 | 30 秒内开始今天的复习 |
| 深度学习者 | 需要追问或整理资料 | 在移动端继续 AI 问答并回到知识上下文 |
| 社区探索者 | 浏览问题、回答和知识文章 | 发现有价值内容并关注贡献者 |

### User Stories & Acceptance Criteria

#### US-1：跨端进入与登录

作为用户，我希望在 App 或微信小程序中快速登录，并在下次打开时回到最近的学习入口。

- 支持用户名密码登录、注册；微信小程序提供微信登录入口。
- Token 统一保存在跨端安全存储中，401 自动清理并跳转登录页。
- 已登录用户启动后进入“今日复习”Tab；未登录用户进入登录页。
- 登录错误在表单附近展示，不重复弹出相同错误。

#### US-2：今日复习留存闭环

作为碎片学习者，我希望打开应用就能看到今日任务、连续天数和清晰的开始按钮。

- 首页首屏展示今日待复习、已完成、完成率和连续学习天数。
- “开始复习”在 2 次点击内进入答题页；无待复习时展示明确的下一步入口。
- 完成复习后显示完成反馈和下一步操作，返回首页后数据刷新。
- 签到、通知、成就和排行榜作为次级入口，不抢占首要 CTA。

#### US-3：知识和 AI 问答

作为深度学习者，我希望从移动端浏览自己的知识并继续 AI 对话。

- 知识 Tab 支持分页/搜索、详情和新建知识入口。
- AI 问答支持进入会话、继续历史上下文；网络异常可重试。
- 私人知识只在当前账户授权范围内展示，跨端不改变原有权限。

#### US-4：社区浏览

作为社区探索者，我希望在移动端浏览问题、回答和作者主页。

- 社区 Tab 展示最新/待回答问题，支持打开详情、查看回答和作者主页。
- 作者主页支持查看公开资料、关注关系和公开贡献；遵守拉黑与隐私规则。
- 小程序页面满足微信导航栈返回规则，App/H5 行为保持一致。

### Non-Goals

- 首发不重写后端 RAG、知识图谱、搜索或研究 Agent。
- 首发不覆盖 Web 的全部管理后台和复杂工作区管理能力。
- 不在客户端保存 API Key、密码明文或私人知识全文缓存。
- 不新增联系请求、私信或校园认证能力；沿用社区后续阶段规划。

## 3. AI System Requirements

### Tool Requirements

- 复用现有 `/api/rag`、`/api/sessions` 和用户 AI 配置接口，不新增移动端 AI 代理。
- 移动端只负责会话展示、请求取消/重试和错误状态，不展示模型 Chain-of-Thought。
- 微信小程序网络域名、App HTTPS 域名和 H5 代理分别配置，禁止把开发地址作为生产默认值。

### Evaluation Strategy

| 能力 | 评估方式 | 门槛 |
|------|----------|------|
| AI 会话连续性 | 50 组跨端登录后续问回归 | 上下文保持率 >= 98% |
| AI 错误恢复 | 模拟超时、401、断网 | 100% 显示可重试状态，不丢当前输入 |
| 移动端首屏 | 低端 Android/WX DevTools 冷启动测试 | 首屏可操作 <= 3 秒 |

## 4. Technical Specifications

### Architecture Overview

```text
App / 微信小程序 / H5
          ↓
      uni-app Vue 3
  ├── Pinia 登录态与工作区状态
  ├── 跨端 request（Token / 401 / 重试）
  ├── 今日复习、知识、AI、社区页面
  └── 平台适配（微信登录、推送、分享）
          ↓
     Spring Boot /api
  ├── 复用现有 Auth、Review、Knowledge、RAG、Community API
  └── 复用 Redis、MySQL、现有通知体系
```

### Integration Points

- `mobile/src/utils/request.js`：统一 API 基地址、Authorization、401 跳转和错误提示。
- `mobile/src/pages.json`：底部主导航固定为复习、知识、广场、我的；AI、社区详情、通知作为栈内页面。
- `mobile/src/stores/user.js`：登录态、用户信息、启动路由和登出清理。
- 微信端使用 `wx.login` 获取 code，再由后端换取平台身份；App 使用用户名密码登录，后续可接推送。
- API 基地址通过环境变量/构建模式注入；生产不允许依赖 localhost。

### Security & Privacy

- Token 仅存储在 uni-app storage；登出、401、账号切换必须清理 Token、用户信息和临时缓存。
- 不记录密码、API Key、AI 对话全文到日志；网络请求失败日志只保留错误类型和请求路径。
- 页面级权限仍以服务端为准；小程序端不能通过隐藏按钮代替鉴权。
- 微信登录、订阅消息和推送权限按需请求，首次启动不强制索取无关权限。

### Phased Rollout

#### MVP（当前阶段）

- 统一移动端设计系统与启动/登录体验。
- 今日复习闭环、知识浏览、AI 问答、社区浏览。
- 修复页面路由与构建问题，完成 H5、App、小程序构建基线。

#### V1.1：留存增强

- 学习提醒、订阅消息、App 本地通知和可配置提醒时间。
- 离线缓存今日复习摘要，弱网下保留未提交答案。
- 移动端社区关注流与个人主页深链。

#### V2.0：跨端协同

- 推送中心、跨端草稿同步、分享卡片和微信会话分享。
- 移动端研究任务进度、报告阅读和知识候选处理。

### Technical Risks

| 风险 | 影响 | 缓解 |
|------|------|------|
| uni-app 平台差异 | 页面或 API 在小程序/App 行为不同 | 统一 service 层，关键页面分别构建验证 |
| 微信域名限制 | 小程序无法请求开发/生产 API | 配置合法 request 域名，开发态明确切换方案 |
| 移动端首屏过重 | 激活率和 D1 留存下降 | 主 Tab 懒加载，首屏只请求复习摘要，图表延后加载 |
| 认证态过期 | 用户频繁回登录页 | 统一 401 处理，保留未发送文本并给出重试提示 |
| 功能过多导致导航拥挤 | 用户找不到今日任务 | 主导航限制 4 项，次级能力收进快捷入口 |

### Release Gates

1. H5、App、微信小程序三种构建命令均通过。
2. 375px、768px、微信常见小程序 viewport 无横向滚动，主要触控目标 >= 44px。
3. 登录、401、启动跳转、复习完成、AI 重试和社区返回路径通过定向测试。
4. 生产构建不包含 localhost API 默认地址和敏感日志。
